| 话题与条数 | `/livox/lidar` 2,772 条；`/livox/imu` 55,435 条 | 与配置的 `points_topic` / `imu_topic` 一致 |

**两条必须记录的经验**

1. **GLIM 自带配置默认指向 GPU 模块，CPU 模式必须手动切换。** 原 `config.json` 指向 `config_odometry_gpu.json`、`config_sub_mapping_gpu.json`、`config_global_mapping_gpu.json`，在 CPU 版包上启动即报 `failed to open libodometry_estimation_gpu.so` → `[critical] failed to load odometry estimation module` → `Aborted`。**必须改为对应的 `_cpu` 版本**。这正是基线「使用 GLIM 的 CPU 模式建立虚拟机复现基线」的具体落地方式，不切就根本跑不起来。
2. **`T_lidar_imu` 是本阶段的假设值。** GLIM 官方文档、wiki 与作者教程均未给出 MID-360 的外参数值（wiki 只写"Change config_sensors.json: sensors/T_lidar_imu"而不给值）；GLIM 对同属 Livox 的 Avia 给出的参考值是单位阵。本阶段采用单位阵，误差量级为毫米到厘米，且 A2 的"墙体重影"检查可反过来验证该假设；**待 B 线接入实机后通过标定或地图质量反推修正**。

- **环境一致性**：由同一模板镜像保证（见 [虚拟机环境基线](虚拟机环境基线.md) 的「环境一致性如何保证」）
