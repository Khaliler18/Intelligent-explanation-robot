## A1. 示例数据与输入检查

本节的目的是确认公开示例数据能被正确读取、且符合 GLIM 的输入要求。**不涉及两台比对**——两台的环境一致性由同一模板镜像保证，理由见 [虚拟机环境基线](虚拟机环境基线.md) 的「环境一致性如何保证」。

- [ ] 从 [GLIM 官方文档](https://koide3.github.io/glim/) 的 Demo data 选择公开雷达与 IMU 示例，记录来源、传感器、格式、校验值和对应配置。
- [ ] 核验话题、消息类型、点时间字段、IMU 单位、外参及时间范围，使用示例对应配置。
- [ ] 需转换为 rosbag2 时保留原件，检查转换后的消息、时间字段和数据完整性。

验收：输入可读取、来源可追溯、格式符合 GLIM 输入要求。

## A2. 离线建图与优化验证

- [ ] 在电脑 A 回放或离线处理示例；核验时间源，使用 ROS 仿真时间时统一 `use_sim_time` 与 `/clock`。
- [ ] 检查轨迹连续性、运动畸变修正、墙体重影、地面及点云覆盖。
- [ ] 验证全局优化与交互式回环修正，检查优化前后地图及错误回环。
- [ ] 如需显式自动回环，评估 [glim_ext](https://github.com/koide3/glim_ext) 的 ScanContext 模块及其维护状态；通过后纳入新基线并同步两台。
- [ ] 保存并重新打开建图工程、轨迹与点云，重复处理同一数据检查结果一致性。
- [ ] 记录命令、配置、日志、耗时、峰值资源占用及已知问题，形成示例复现步骤。

验收：示例完整处理，地图和工程可恢复，建图与优化过程可重复。

## A3. 自采数据跨机复现

本节与"两机交叉验证"无关，验证的是另一件事：**B 线采集的真实数据，能否在电脑 A 上重建出三维地图**。这是 B 线 B3/B4 的前置条件，也是"地图接口可替换"的实际检验。

- [ ] 接收 B 线自采原始记录、标定参数与配置，校验文件完整性。
- [ ] 在电脑 A 复现三维地图，与电脑 B 的结果比对。
- [ ] 记录跨机复现的差异、耗时与结论。

验收：B 线自采数据可在电脑 A 重建，两台均可使用同一份原始记录与配置完成建图。

## A4. 地图接口验证

- [ ] 将官方示例输出整理为独立地图数据集，包含元数据、点云或建图工程、配置和质量检查记录。
- [ ] 通过地图数据集路径或地图 ID 加载示例地图，确认流程不依赖固定文件名、固定区域名称或绝对路径。
- [ ] 复制一份地图数据集并只修改版本与元数据，验证替换地图不需要修改通用加载接口。
