# 博物馆讲解具身智能机器人

## 项目简介

本项目面向博物馆讲解场景，打造一套搭载在智能移动小车上的具身智能机器人。机器人能够在博物馆环境中移动，通过本地模型与云端大模型协同工作，为参观者提供自然、连续的讲解与交互服务。

## 核心形态

- **移动平台**：具备智能避障等能力的小车，承载机器人本体并支持自主移动。
- **本地智能**：在机器人端部署裁剪后的小模型，承担本地推理、实时响应及必要的离线能力。
- **云端协同**：连接云端大体量模型，提供更强的理解、生成与复杂任务处理能力。
- **多模态交互**：支持语言交流、视觉感知等多模态能力，提升讲解和互动体验。
- **RFID 互动讲解**：识别展品或区域对应的 RFID 标签，根据用户需求顺序进行针对性讲解。

## 项目愿景

让博物馆讲解机器人能够在真实环境中自主移动、感知周围信息、理解参观者需求，并结合展品 RFID 标签提供灵活、有序的个性化讲解服务。

## 当前状态

项目处于**A 线铺路完成、B 线实机建图待开始**阶段。

**A 线（电脑 A）已完成**：环境基线建立并验证（Ubuntu 22.04.5 + ROS 2 Humble + GLIM 1.2.2 + Livox SDK2/驱动），用公开的 **Livox MID-360 示例数据**跑通完整离线建图流程（277 秒数据约 50 秒处理完，地图质量验收通过，工程可保存并重新加载），并沉淀出配置、操作流程与避坑记录。标准模板交付包（基线编号 `SLAM-TPL-v1`）已生成，用于部署电脑 B。

**B 线（电脑 B）下一步**：用交付包部署环境 → 接入 MID-360 → 测试区域扫描 → 离线建图 → 地图数据集交付。操作手册见 [MID-360 实机建图操作流程](docs/01-slam/MID-360实机建图流程.md)。

**A 线的作用到此结束**——B 线独立完成实机工作，不需要两机交叉验证（环境一致性由同一模板镜像保证）。

技术路线：采用 **GLIM + ROS 2 Humble + Livox MID-360**，先跑通公开示例，再人工采集真实区域的雷达与 IMU 数据，进行离线三维 SLAM 建图。地图验收后，制作对应的仿真场景和导航地图，用于小车算法验证，最后迁移到真实机器人。

**即将进行的扫描只是流程验证**，实际项目区域将在后续重新扫描，生成**新的地图 ID 与版本**。地图数据集接口从设计上支持直接替换，不需要修改加载、坐标与导航程序。

## 环境要求

| 项目 | 要求与说明 |
| --- | --- |
| 操作系统 | 虚拟机内运行 Ubuntu 22.04 LTS，作为 ROS 2 Humble 的开发基线 |
| 虚拟机配置 | 两台电脑由同一标准模板部署；虚拟机平台、系统、vCPU、内存、磁盘、显示、软件及运行配置完全一致，分别验证图形显示并保存基线快照 |
| 网络 | 两台使用相同的 NAT 与桥接虚拟网卡配置，分别用于下载与雷达采集；验证 UDP 数据收发，同时联网时使用唯一实例标识及 IP，并记录物理网卡映射 |
| ROS 框架 | ROS 2 Humble；使用 rosbag2 记录与离线播放数据，使用 RViz2 检查点云、轨迹和坐标系 |
| SLAM | [GLIM](https://github.com/koide3/glim) 与 glim_ros，用于雷达与 IMU 融合的三维建图。ROS 2 包名为 `glim_ros`（不是文档中常见的 `glim_ros2`） |
| 雷达驱动 | [livox_ros_driver2](https://github.com/Livox-SDK/livox_ros_driver2) 及其所需的 Livox SDK2；核验点云消息、每点时间与 GLIM 输入的兼容性 |
| 依赖与版本 | **经 2026-10-13 验证，GLIM 及 GTSAM、gtsam_points、iridescence 等依赖已提供预编译包，无需源码编译。** 按 [GLIM 官方安装文档](https://koide3.github.io/glim/installation.html) 的 PPA 方式安装，选**不带 CUDA** 的包以对应 CPU 模式；按 apt 版本号精确安装并记录，不装"当时的最新版" |
| 计算模式 | 使用 GLIM 的 CPU 模式建立虚拟机复现基线；GPU 加速需另行验证虚拟机 GPU 支持、CUDA、驱动和模块配置 |
| 回环与精修 | 使用 GLIM 的全局优化与交互式地图修正；[glim_ext](https://github.com/koide3/glim_ext) 中的显式回环模块先单独验证，暂不作为必需依赖 |

虚拟机软件、资源分配、依赖版本、网络设置和运行结果统一记录在阶段文档中。配置变更同步到标准模板和两台虚拟机，以相同示例数据进行交叉验收。

## 已部署环境版本

**基线编号 `SLAM-TPL-v1`**，2026-10-13 于电脑 A 实测。电脑 B 由同一模板部署，版本须与此表完全一致。

| 组件 | 版本 |
| --- | --- |
| 操作系统 | Ubuntu 22.04.5 LTS（UEFI 启动，ESP + ext4，无 LVM/加密）；内核 `6.8.0-138-generic` |
| 虚拟机 | VMware Workstation Pro 17.5.0；8 vCPU（1×8）/ 16 GB 内存 / 100 GiB 单一虚拟磁盘 / 2 GB 显存 / NAT + 桥接双网卡 |
| ROS 2 | Humble，共 282 个 `ros-humble-*` 包，含 RViz2 与 rosbag2 |
| GLIM | `ros-humble-glim`、`ros-humble-glim-ros` **1.2.2-0jammy** |
| GTSAM | `libgtsam-notbb-dev` **4.3.0** |
| gtsam_points | `libgtsam-points-dev` **1.2.2** |
| iridescence | `libiridescence-dev` **1.0.2** |
| Livox SDK2 | 源码编译，commit `c0796f04c143143899c87a773d9f6b7136453c0b` |
| livox_ros_driver2 | 源码编译，commit `21445540f0d100dc86a7e6df312dd70bbdb4afdf` |
| 计算模式 | CPU 模式（依赖均选不带 CUDA 的版本） |

**交付包**：`B环境\`（21.48 GB），含两层基线快照、[部署文档](B环境/部署文档.md)与[逐文件 SHA-256 校验值](B环境/校验值.txt)，用于部署电脑 B。软件源配置、网络环境限制、关键路径与完整验证记录见 [SLAM A 虚拟机环境](docs/01-slam/SLAM_A虚拟机环境.md) 第八、九节。

**已知的宿主机前提**：两台宿主机都必须关闭 Hyper-V/VBS 相关功能，否则 VMware 会退到 `Monitor Mode: ULM`，性能下降一个数量级。处理步骤见 [虚拟机环境基线](docs/01-slam/虚拟机环境基线.md) 的「宿主机前提」。
